Using ISU's Azure AI Foundry models

Sign in once with your ISU account, then use the university's LLM deployments from the terminal, from Python, and from the coding tools you already use — VS Code, Codex, OpenCode, AnythingLLM and more.

Time about 15 minutes Cost free with your ISU account Works on Windows, macOS, Linux Verified 19 Aug 2026

What you're connecting to

ISU runs a set of large language models on Microsoft's Azure AI Foundry. You reach them at a normal HTTPS endpoint that speaks the OpenAI API format — so most tools that work with OpenAI work here, once you point them at ISU's address.

The one thing that's different: there is no permanent API key. You sign in with your ISU account and receive a token that expires after about an hour. Step 8 explains how to live with that.

The models you can use

Model name (type this exactly)TextToolsImages inUse it for
Llama-4-Maverick-17B-128E-Instruct-FP8YesYesYesThe best all-rounder. Start here.
Llama-4-Scout-17B-16E-InstructYesNoYesImages and text. Tool calling is broken — see below.
gpt-oss-120bYesYesNoReasoning tasks. Needs a high max_tokens.
Phi-4-mini-instructYesYesNoA small, fast model. Good for comparisons.
Two traps that waste everyone's afternoon

1. Llama-4-Scout cannot call tools. Ask it to use a function and it returns an empty response with no error at all. If you are building an agent, use Llama-4-Maverick or gpt-oss-120b instead.

2. gpt-oss-120b returns an empty answer if max_tokens is small. It thinks privately before it writes, and that thinking consumes your token budget. At max_tokens=32 you get an empty string and no error. Always give it at least 512.

Not available yet

There is currently no embedding model and no speech/audio model on this endpoint. If your course needs retrieval-augmented generation (RAG) or speech recognition, you will need another source for those pieces for now — ITS has been asked to add them.

Install the Azure CLI

A small command-line program that handles the ISU sign-in for you.

Open PowerShell (press Win, type PowerShell, press Enter) and run:

PowerShell
winget install --exact --id Microsoft.AzureCLI

If winget isn't available, download and run the installer instead:

PowerShell — alternative
Invoke-WebRequest -Uri https://aka.ms/installazurecliwindowsx64 -OutFile .\AzureCLI.msi
Start-Process msiexec.exe -Wait -ArgumentList '/I', '.\AzureCLI.msi', '/quiet'
Remove-Item .\AzureCLI.msi
Close PowerShell and open it again

This step catches almost everyone. The installer adds az to your system path, but any window that was already open still has the old path and will say 'az' is not recognized. Close every PowerShell window and open a fresh one. You do not need to reinstall anything.

Open Terminal (press ⌘Space, type Terminal, press Enter). If you don't already have Homebrew, install it first:

Terminal — only if you lack Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Then install the Azure CLI:

Terminal
brew update && brew install azure-cli
If az breaks after a Homebrew upgrade

Homebrew's build of az relies on a separately installed Python, so an unrelated brew upgrade can break it with Unable to find Python or installed packages. The fix: brew install python@3.10 && brew link --overwrite python@3.10

On Ubuntu or Debian, one command does everything:

Ubuntu / Debian
curl -sL https://aka.ms/InstallAzureCLIDeb | sudo bash

On Fedora, RHEL or CentOS Stream:

Fedora / RHEL
sudo rpm --import https://packages.microsoft.com/keys/microsoft.asc
sudo dnf install -y https://packages.microsoft.com/config/rhel/9.0/packages-microsoft-prod.rpm
sudo dnf install -y azure-cli
Unsupported distribution?

Mint, Pop!_OS and newer Ubuntu releases sometimes report a codename Microsoft's repository doesn't recognise. Set it manually before installing: AZ_REPO=jammy for Ubuntu-based systems, or AZ_REPO=bookworm for Debian-based ones.

Check it worked

Any system
az version

You should see a version number, something like 2.89.1. If you instead see command not found or not recognized, close the terminal, open a new one, and try again.

3

Get your access token

This is the string you'll paste wherever a tool asks for an "API key".

PowerShell
$env:FOUNDRY_TOKEN = (az account get-access-token `
    --resource https://ai.azure.com `
    --query accessToken -o tsv).Trim()

# Copy it to the clipboard, ready to paste into any app:
Set-Clipboard $env:FOUNDRY_TOKEN
Write-Host "Token copied. Length: $($env:FOUNDRY_TOKEN.Length)"
Terminal
export FOUNDRY_TOKEN=$(az account get-access-token \
    --resource https://ai.azure.com \
    --query accessToken -o tsv)

# Copy it to the clipboard, ready to paste into any app:
echo -n "$FOUNDRY_TOKEN" | pbcopy
echo "Token copied. Length: ${#FOUNDRY_TOKEN}"
Terminal
export FOUNDRY_TOKEN=$(az account get-access-token \
    --resource https://ai.azure.com \
    --query accessToken -o tsv)

# Copy it to the clipboard (install xclip first if needed):
echo -n "$FOUNDRY_TOKEN" | xclip -selection clipboard
echo "Token copied. Length: ${#FOUNDRY_TOKEN}"

The token is a long string of letters and numbers, usually well over a thousand characters. That is normal — it is a signed document describing who you are, not a password.

Treat this like a password anyway

Your token carries your full ISU identity for about an hour. Do not commit it to GitHub, paste it into a shared document, or include it in a screenshot. If you think you have leaked one, run az logout — and remember it expires on its own shortly anyway.

When does it expire?

Any system
az account get-access-token --resource https://ai.azure.com --query expiresOn -o tsv

Typically 60 to 90 minutes from now. When it expires, tools stop working and usually say something unhelpful like 401 or connection failed. Just run the command in this step again to get a fresh one. Step 8 shows how to make this painless.

5

Look around the Azure dashboard

Optional, but useful for instructors who want to see what's deployed and how much is being used.

There are two different web consoles, and knowing which is which saves a lot of confusion:

  • ai.azure.com — the Foundry portal. Chat with the models in a browser, and see which ones are deployed. This is the one most people want.
  • portal.azure.com — the Azure portal. Billing, usage metrics, quota and permissions. Mostly of interest to instructors and ITS.

The Foundry portal: chatting without installing anything

Sign in with your ISU account, pick the foundry-faculty-instruction resource, then open Playgrounds. This is the fastest way to let students try a model on day one — no terminal, no token, no setup at all.

Why you can't get this list from the API

You might expect GET /openai/v1/models to tell you what's deployed. On this endpoint it doesn't — it returns Microsoft's entire catalogue of 403 models, almost none of which are available to you. Trust the Deployments page, or the table at the top of this guide.

The Azure portal: usage and quota

Instructors who want to see how much a class is consuming will find it under the resource's Metrics blade. Ask ITS for the Cognitive Services Usages Reader and Cost Management Reader roles if these pages are empty for you.

6

Use it from Python

The recommended approach for coursework — and the only one that never expires mid-session.

Install
pip install "openai>=1.106.0" azure-identity

Here is the pattern to teach. The important detail is subtle but decisive: api_key is given a function, not a string. The OpenAI library calls that function before every request, so a fresh token is fetched automatically and your program never dies of an expired token.

foundry.py
from openai import OpenAI
from azure.identity import AzureCliCredential, get_bearer_token_provider

# Reuses the `az login` you already did. Refreshes silently, forever.
token_provider = get_bearer_token_provider(
    AzureCliCredential(),
    "https://ai.azure.com/.default",
)

client = OpenAI(
    base_url="https://foundry-faculty-instruction.services.ai.azure.com/openai/v1/",
    api_key=token_provider,   # a function, not a string. This is the whole trick.
    max_retries=5,
    timeout=120.0,
)

response = client.chat.completions.create(
    model="Llama-4-Maverick-17B-128E-Instruct-FP8",
    messages=[{"role": "user", "content": "Explain a hash table in two sentences."}],
    max_tokens=512,
)

print(response.choices[0].message.content)
No Azure CLI? There's a pure-Python route

If a student can't install the CLI — a locked-down laptop, a lab machine, a Chromebook with a Linux container — pip install azure-identity is enough on its own. Swap the credential and it prints a short code to enter at microsoft.com/devicelogin:

No CLI required
from azure.identity import DeviceCodeCredential, TokenCachePersistenceOptions

credential = DeviceCodeCredential(
    tenant_id="0347d89a-0174-4dd3-adeb-3339c89c35f5",
    cache_persistence_options=TokenCachePersistenceOptions(),  # sign in once, not every run
)
token_provider = get_bearer_token_provider(credential, "https://ai.azure.com/.default")

Nothing else in the program changes.

Checking for the silent failures

Two of the traps described at the top of this page produce no error at all. Teach students to check finish_reason:

Worth putting in every assignment template
choice = response.choices[0]

if choice.finish_reason == "length":
    print("!! Ran out of tokens before finishing. Raise max_tokens.")
elif choice.finish_reason == "content_filter":
    print("!! Azure's safety filter blocked this. Rephrase the prompt.")
elif not choice.message.content:
    print("!! Empty answer. If this is gpt-oss-120b, raise max_tokens to 512+.")
else:
    print(choice.message.content)

Connect your coding tools

Almost every tool needs the same two values. Learn the pattern once and the rest is filling in boxes.

The universal recipe

Whenever an application asks you to configure an AI provider, choose the option called "OpenAI", "OpenAI Compatible" or "Custom Endpoint" — never the one branded "Azure OpenAI", which expects a different URL shape and will fail. Then enter:

Base URLhttps://foundry-faculty-instruction.services.ai.azure.com/openai/v1
API Keyyour token from step 3 (the whole long string)
Modela name from the table at the top, e.g. Llama-4-Maverick-17B-128E-Instruct-FP8
API Versionleave completely empty if the app offers this field
Anything you paste a token into will stop working in about an hour

Graphical apps store the token as fixed text; they cannot refresh it. When a tool suddenly returns 401 or "connection failed", the token has simply expired — redo step 3 and paste the new one. Step 8 makes this a one-word command. Only Python (step 6) and the two clients marked self-refreshing below avoid this entirely.

Claude Code cannot use these models

This one is worth stating plainly because it is asked constantly. Claude Code speaks only Anthropic's own protocol, so it cannot talk to Llama or gpt-oss at all — no configuration will change that.

It does have excellent built-in Azure Foundry support, and it would refresh tokens automatically via az login. It is blocked purely because ISU has not deployed any Claude models. Don't drop the requestHeaders line

VS Code recognises the azure.com address and, left to itself, sends the credential as an api-key header. This endpoint needs Authorization: Bearer. That single line is the difference between working and a baffling 401.

VS Code — Continue, Cline or Roo Code

For Cline and Roo Code, open their settings and pick provider OpenAI Compatible, then fill in the universal recipe. Leave any Azure API Version box empty — filling it switches the extension to a different URL format that this endpoint does not serve.

For Continue, edit ~/.continue/config.yaml (%USERPROFILE%\.continue\config.yaml on Windows):

config.yaml
name: isu-foundry
version: 0.0.1
schema: v1
models:
  - name: ISU Llama 4 Maverick
    provider: openai            # 'openai', NOT 'azure'
    model: Llama-4-Maverick-17B-128E-Instruct-FP8
    apiBase: https://foundry-faculty-instruction.services.ai.azure.com/openai/v1/
    requestOptions:
      headers:
        Authorization: "Bearer PASTE_YOUR_TOKEN_HERE"
    roles: [chat, edit, apply]

8

Make refreshing the token painless

Add this once and getting a fresh token becomes a single short word.

Open your PowerShell profile:

PowerShell
if (-not (Test-Path $PROFILE)) { New-Item -ItemType File -Path $PROFILE -Force }
notepad $PROFILE

Paste this at the bottom, save, then close and reopen PowerShell:

Add to your PowerShell profile
function foundry {
    $env:FOUNDRY_TOKEN = (az account get-access-token `
        --resource https://ai.azure.com --query accessToken -o tsv).Trim()
    $env:OPENAI_API_KEY  = $env:FOUNDRY_TOKEN
    $env:OPENAI_BASE_URL = "https://foundry-faculty-instruction.services.ai.azure.com/openai/v1"
    Set-Clipboard $env:FOUNDRY_TOKEN
    Write-Host "Fresh ISU Foundry token ready (also copied to clipboard)." -ForegroundColor Green
}

Add this to ~/.zshrc (the default shell on macOS), then run source ~/.zshrc:

Add to ~/.zshrc
foundry() {
  export FOUNDRY_TOKEN=$(az account get-access-token \
      --resource https://ai.azure.com --query accessToken -o tsv)
  export OPENAI_API_KEY="$FOUNDRY_TOKEN"
  export OPENAI_BASE_URL="https://foundry-faculty-instruction.services.ai.azure.com/openai/v1"
  echo -n "$FOUNDRY_TOKEN" | pbcopy
  echo "Fresh ISU Foundry token ready (also copied to clipboard)."
}

Add this to ~/.bashrc, then run source ~/.bashrc:

Add to ~/.bashrc
foundry() {
  export FOUNDRY_TOKEN=$(az account get-access-token \
      --resource https://ai.azure.com --query accessToken -o tsv)
  export OPENAI_API_KEY="$FOUNDRY_TOKEN"
  export OPENAI_BASE_URL="https://foundry-faculty-instruction.services.ai.azure.com/openai/v1"
  command -v xclip >/dev/null && echo -n "$FOUNDRY_TOKEN" | xclip -selection clipboard
  echo "Fresh ISU Foundry token ready."
}

Now, whenever anything stops working, type foundry and carry on. It also sets OPENAI_API_KEY and OPENAI_BASE_URL, which many command-line tools read automatically — so tools launched from that terminal often need no configuration at all.

You will not have to sign in again

The Azure CLI keeps a longer-lived credential on disk, so refreshing the token is instant and silent. You typically only repeat step 2 every few weeks.

When something goes wrong

Nearly every problem is one of these six.

What you seeWhat it meansFix
'az' is not recognized
command not found: az		 The terminal was open before you installed the CLI, so it has a stale search path. Close every terminal window and open a new one. Do not reinstall.
401 or connection failed, after it had been working Your token expired. This is the single most common problem. Run foundry (step 8) and paste the new token.
401 Principal does not have access You are signed in correctly, but your account hasn't been granted the models yet. Wait 5 minutes if you were just added, then az logout and sign in again. Still failing? Contact your instructor.
404 The model name is wrong, or the address has /v1 twice. Copy the model name exactly from the table at the top. Check for /openai/v1/v1/ in the URL — some apps add /v1 themselves, so try ending the Base URL at /openai.
429 Too many requests at once — often a whole lab running the same cell. Wait a few seconds and retry. In Python, max_retries=5 handles this for you.
Empty answer, no error Either gpt-oss-120b with too small a max_tokens, or a tool call on Llama-4-Scout. Raise max_tokens to 512+, or switch to Llama-4-Maverick.

Still stuck? Collect this before asking for help

Any system
az account show --query "{user:user.name, tenant:tenantId}" -o json
az version
az account get-access-token --resource https://ai.azure.com --query expiresOn -o tsv

Those three outputs — with the token itself never included — are enough to diagnose almost anything.

★

Notes for instructors

Things worth knowing before you build a course around this.

The expiring token is a real problem at class scale

A student in a 75-minute lab will usually hit the expiry once. For a class of 100 that is a meaningful support load, and the workaround — teaching students to paste a credential carrying their full ISU identity into third-party applications — is worse for security than the API keys this system replaced.

The durable fix is a small gateway (LiteLLM is the usual choice) that holds one service credential, refreshes it automatically, and issues each student a permanent key with their own budget and rate limit. That also gives you per-student usage accounting, which Foundry does not provide on its own. It requires ITS to create a service principal or managed identity for the course.

Design assignments around what actually works

  • Agents and function calling: Llama-4-Maverick or gpt-oss-120b only. Never Llama-4-Scout.
  • Images: Llama-4-Maverick or Llama-4-Scout.
  • Long outputs: Llama-4-Maverick or gpt-oss-120b. Scout caps at 8,192 output tokens.
  • Retrieval / RAG: not currently possible on ISU infrastructure — no embedding model is deployed.
  • Speech and audio: not currently possible either.

Ask ITS for a security group, not individual access

Have ITS assign the role to an Entra security group for your roster rather than to 100 individual accounts. Group membership takes effect immediately, whereas a fresh individual role assignment can take five minutes to work — which is exactly the kind of thing that derails a first lab session.

Don't run red-teaming exercises on this endpoint

Microsoft's abuse monitoring flags repeated jailbreak attempts, and the documented consequence is suspension of access — potentially for the whole university, not just your class. If you want to teach adversarial prompting or safety evaluation, use a locally hosted model instead.

Set token budgets in your assignment templates

Azure's rate limiter counts prompt tokens + max_tokens, not the tokens actually produced. A student who leaves max_tokens=4000 on a question with a forty-token answer still consumes four thousand tokens of the shared class allowance. Put a sensible max_tokens in every starter file.
